## 2. Findings from the read (worth acting on)

1. **Side slab reads are silently dropped — latent bug.** `isMissedCapture` in `src/vision/extractFrame.ts` discards any air race whose candidates aren't all two-word names (added in `d12428c` to drop mid-transition ticker frames). But the side slab shows **surnames only by design** (`recordings/reference-frames/slab-2.png`: "CLARK", "KIMES"; `sideSlab.ts` even says "the candidate surname"). Every `side_slab` observation is therefore filtered out before it reaches the store. No frame golden covers the slab, so the suite can't see it, and the NEXT_STEPS note "RESOLVED: no template shows surnames only" is wrong for this template. Fix in §4 Phase 1.4.
2. **Hysteresis was designed but never built.** `thresholds.ts` defines `airHysteresisN`, `vendorHysteresisN`, `recoveryHysteresisM`, `inBreakSilenceMs`; nothing reads them. `anomalyTracker` replaces a race's anomaly set on every reconcile, so a single-frame VLM misread becomes an immediate high alert that clears on the next capture. This is the same "one-poll blink" the primary-night audit found, and it will pollute an alert-history log if that lands first. Fix in §4 Phase 2.1.
3. **`dataPath` is declared but never consumed.** The reconciler always runs air-vs-vendor rules. Harmless until a `provider_direct` (magic wall) template exists. Note only.
4. **Frame disk budget.** Every capture writes a full PNG (~1.5 MB at 1920-wide). At the default 5 s cadence that is ~1 GB/hour, ~6 GB for a 6-hour broadcast. Not a bug (PNG bytes are what the replay hash keys on), but the recording disk needs headroom and old session frame dirs need pruning.
5. **Missing fixture.** `chameleon_response_example.json` is a runoff; there is no General-election Chameleon contest sample. The next big night is the **Nov 3, 2026 midterm general** (statewide Senate/Governor, `party: null` → `NP` in `composeRaceKey` on both sides). Cheap to verify with a real sample before then.
6. **Air→DDHQ linking is proposal-driven, not deterministic.** `descriptorFromObservation` normalizes the raw source key; for air that is the uppercased race heading, which never equals a DDHQ key, so air races always go provisional → one Haiku proposal → human accept. That worked in June (10 accepted). A heading-format change in the new package only changes the proposal's descriptor text, so identity is low-risk in the refresh.
